CH 3 · 实现原理

上下文有三道闸 —— 逆向最要命的是工具输出那道

注释写得很直白：objdump -d / strings 这类命令就是会吐兆字节，原样倒进 transcript 等于一次性烧掉整个窗口。

会话是只追加的 JSONL

  • 每行一条 {Type, Timestamp, Data}，三种类型：session / message / event。O_APPEND + mutex，文件名带 UTC 时间戳

恢复路径处理得很硬核

  • 解析失败的行静默跳过，注释：「会话被写到一半杀掉时，末行截断是预期内的」
  • repair() 双向修剪：有 call 无 result 就摘掉 call，有 result 无 call 就丢掉 result —— 两种都会被 provider 拒收

同页的代价：三道闸都是「丢信息」

  • 省略掉的 tool result、丢掉的老对话、被 head/tail 切走的中段 —— 模型都看不见了
  • 逆向恰恰是两小时前那个不起眼的字符串突然变关键的场景。这里没有语义索引，只有「你自己记得去读那个 artifact 文件」
