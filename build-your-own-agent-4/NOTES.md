## 0. 必须在台上说的一句话

**本讲主讲人就是 re-agent 的作者。** 这句话写在第 02 页上，讲之前口头再说一次。

理由不是客气：讲别人的项目，读者的怀疑会自动抵消你的偏见；讲自己的项目，读者的怀疑**往往还不够**。所以本讲的自律是三条，全部落到了页面上：

1. **优点页配代价** —— 凡讲一条长处，同页必须给出它的局限或成本。全场没有一页只有好话。
2. **对比章先自我拆台** —— 第 22 页整页在说「这六条其实 pi/omp 配一下也有」，第 23 页才说剩下四条。**顺序不能换**。

## 3. 会被问到的六个问题，和准备好的答法

### Q1「这跟给 Claude Code 写一堆 skill 有什么区别？」

**两边都讲**：只约束单个 agent 的行为，skills + hooks 就够了 —— 第 22 页 C1 已经承认了这一点。多做一层的理由只有两个：**要跨两个 CLI 编排**，**要一份统一可重放的轨迹**。这两件事在单个 CLI 里做不了。

其余的（skill、prompt、工具清单、审批闸、MCP）**我在第 22 页自己拆掉了**，别在 Q&A 里又捡回来。

### Q2「测试比 0.17 倍，这东西能用吗？」

不洗。答：**能用和能托付是两件事。** 它现在的定位是「作者自己每天用的工具」，不是「你可以放进 CI 的组件」。第 21 页那一格标红就是这个意思。

### Q3「默认 safe 档对 tier 一律放行，那这个审批闸还有什么用？」

**这是最尖锐的一问，必须正面接。** 答：目前真正拦住东西的是**命令正则 concerns** 和 **executor 的只读白名单**，不是 tier 闸。tier 闸在 `always-ask` 档下才完整生效。而且实际跑起来时，很大一部分沙箱来自默认 provider（Codex CLI 自带的 `--sandbox read-only`）—— **那是别人的功劳，第 22 页写了**。

### Q4「maxTurns 只有 8，真实逆向任务够吗？」

不够。这是**保守，不是严谨**。缓解手段是 caveman 的两阶段拆分（一次请求变成两个各自 8 轮的 loop）和队列续跑，但这不是解决方案。第 21 页和第 22 页各标了一次。

### Q5「为什么不 fork pi 或 oh-my-pi，非要从零写？」

第 23 页那四条就是答案，但要补一句诚实的：**四条里只有 S3（隔离委派）是真从领域推出来的**，S1/S2/S4 更像是「一个人写代码时的偏好」得到了事后合理化。作者自己那句「几乎每一条差异都从『读二进制 vs 改代码』推得出来」被第 22 页拆掉了 —— **实际大约只有三分之一**。

### Q6「一个人能长期维护吗？」

答不好就别硬答。可以说的：**分发只有 `go install` 一条路，没有 Releases 二进制、没有 brew、没有 Docker** —— 一个宣称「静态单二进制、scp 过去就能用」的项目却不发布二进制，这个矛盾第 28 页写了。可持续性目前没有答案，**别在台上编**。

## 4.5 定稿前跑了一遍对抗式复核，改掉了 21 处

做完初稿后，用一个独立的核查流程把**每一个数字、每一个 `file:line`、每一句英文引文**重新对源码验了一遍（约 135 条断言）。改掉的 21 处里，值得记住的几类：

| 类型 | 例子 |
|---|---|
| **数字被自己的研究笔记打脸** | `internal/providers` 页面上写 3,300+ 行，笔记里明明写着实测 **2,474** —— 而那页副标题恰好承诺「全场数字来自本地 find + wc -l」 |
| **口径没定义清楚就报数** | skill 常驻目录原写 7,258 字节，但那只是 name+description 的裸和；按 `SystemPrompt` 真实拼法（含 `- `、`: `、换行、以及**目录名兜底当 tag**）应为 **8,531**，比例从 1:55 修正为 **1:47** |
| **把 help 分组当成实现** | 「16 条走 `runDirectTool`」错了 —— 16 是 help 里 direct tools 那一组的条数，真正走 `runDirectTool` 的是 **11** |
| **引文少了两个词** | `"Treat unknown as a prompt for deeper analysis…"` 原文是 `deeper **tool-specific** analysis` |
| **把 prompt 说成注释** | caveman 那句红线不是代码注释，是**发给模型的 prompt 文本**；而且原句还有半截「to bypass a model or site policy」，那半截**限定了禁令范围**，不能省 |
| **同页自相矛盾** | 一处说 burp/mitmproxy「照跑」，另一处说它们「只吐模板」。实情：**只有 frida 会真起进程**，burp/mitmproxy 只返回模板 |
| **算术不闭合** | 「10 通用 + 1 + 4 基础设施 + 7 领域原语」= 22 ≠ 24；基础设施其实是 5 个，还漏了 `frida_hook_template` |
| **绝对化的否定句** | 「全仓没有 `EvalSymlinks`」是假的（`assets.go:52` 有一处）。论点仍成立 —— `ResolveInside` 确实不解 symlink —— 但话不能那么说 |
| **拿不到的证据说成实测** | 「没有 Releases 二进制」是 github.com 站点侧事实，不是 commit `926e615` 里的事实，已改标 [B] |

**这一节本身就是台上可以讲的内容**：讲自家项目时，最危险的不是撒谎，是**顺手取一个「差不多」的数**，而听众根本没法分辨。
