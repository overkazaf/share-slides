Loop Engineering："转圈"是最容易被低估的那部分

教科书里的 agent loop 是 while(true){ llm(); tools(); }。真实实现里，难的全在中断、插队、判停、截断、并发和错误恢复。pi 的主循环是双层 while，这个设计值得抄。

判停：四种收敛条件

  • 模型这轮不再要工具（最常见）
  • 到达最大轮数上限
  • 工具返回 terminate 信号pi 要求批次内每一个结果都 terminate 才停
  • 用户中断 / 出错

三个容易踩的坑

  • 没有超时：pi 把超时交给工具自己管，bash 工具的 timeout 默认不设 —— 你得自己想清楚
  • 并行写同一个文件：按真实路径（软链接同锁）串行化，否则并行编辑会丢更新
  • 报错就是养料：错误带字段路径回喂模型，比"执行失败"有用一百倍

可借鉴

  • UI 按完成顺序更新，历史按源顺序写 —— 体验实时，记录可重放
  • 能力层永不抛异常，一律返回 Result<T,E>
