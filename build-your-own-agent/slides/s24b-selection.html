再看用法：为什么我这样搭

每条用法尽量挂量化依据；纯经验判断我会直说。

Claude Code

主力
  • 闭环最完整：改完能跑、挂了能看见、能改回来

Codex

派活
  • 独立沙箱 + 独立 git 状态：形状已知的活派完撒手，回来收 PR

Gemini Notebook

消化
  • 只从你给的材料里答（source-grounded），能确认它没编

Grok

探风向
  • 接 X 实时流：真实用户在骂什么 —— 官方博客不会告诉你
任务类型首选量化依据
深度重构 / 跑测试Claude Code + Opus 5 评测必须真跑测试
日常八成的活Claude Code + Sonnet 5 $2/$10 vs $5/$25，便宜 2.5 倍
长时并行 / 批量 PRCodex 云端 + Terra $2/$12，甜点价
批量粗筛 / 过日志GPT-5.6 Luna $0.20/$1.20，比同代旗舰便宜 25 倍
跨仓库大规模检索子代理扇出 上下文隔离，代价 token 放大
长文档消化带引用Gemini Notebook 无量化对比，凭经验
私有化 / 数据不出境开放权重自建 短任务差 0.5–7 分、价差 4.6–57 倍；长程仍差 12–21 分

必须说清的诚实结论

  • Terminal-Bench 榜上 Claude Code 默认配置不是最高分：同一个 Opus 4.6，最好的 harness 76.4%，Claude Code 58.0%
  • 选它不是因为跑分高，是因为扩展点最齐 —— 别混为一谈

选型心法

  • 按"人在不在场"分类比品牌有用：
    人在场 → 终端 / 编辑器；不在场 → 云端异步；人在读 → 检索型
  • 默认便宜档，卡住再升 —— 不是反过来
