再看用法：为什么我这样搭

牌面看完了，关键是怎么出。下面每条用法我都尽量挂了量化依据；纯经验判断的地方，我会直说是经验判断。

Claude Code

主力
  • 因为闭环最完整：改完能跑、跑挂了能看见、看见了能改回来
  • 真正的杀手锏不是模型，是 skills / hooks —— 把团队规范固化成强约束，而不是每次靠嘴说

Codex

派活
  • 因为每个任务有独立沙箱 + 独立 git 状态，互不污染
  • 批量升依赖 / 批量修 lint 这类形状已知的重复劳动，派发完就撒手，回来收 PR

Gemini Notebook

消化
  • 因为它只从你给的材料里答 —— 要的就是"我能确认它没编"
  • 通用长上下文会"读着读着跑偏"，source-grounded 是结构性地堵住这个口子

Grok

探风向
  • 因为它接 X 的实时流，官方定位原话就是 agentic coding
  • 新东西刚发布时，真实用户此刻在骂什么 —— 官方博客永远不会告诉你
任务类型首选为什么是它（量化依据）
深度重构 / 要跑测试验证Claude Code + Opus 5 这类任务的评测本身就必须真跑测试才算过 —— 生成式基准衡量不了
日常八成的活Claude Code + Sonnet 5 $2/$10 对 $5/$25，便宜 2.5 倍；卡住了再升 Opus
长时并行 / 批量 PRCodex 云端 + Terra 独立沙箱 + 独立 git 状态；$2/$12 是这档吞吐量下的甜点价
批量粗筛 / 分类 / 过日志GPT-5.6 Luna $0.20/$1.20，比同代旗舰便宜 25 倍 —— 这种活不该用贵模型
跨仓库检索 / 大规模理解子代理扇出 官方口径：子代理主要收益是上下文隔离，代价是 token 放大
长文档消化，要带引用Gemini Notebook 答案锚定源材料；此项无公开量化对比，属经验判断
私有化 / 数据不出境开放权重自建 短任务差 0.5–7 分、价格差 4.6–57 倍；但长程仓库级任务仍差 12–21 分

一条必须说清的诚实结论

  • Terminal-Bench 官方榜上，Claude Code 的默认配置并不是分数最高的（同一个 Opus 4.6，最好的 harness 76.4%，Claude Code 58.0%）
  • 我选它不是因为它跑分最高，是因为它的扩展点最齐、我能把规范焊进去 —— 这是两回事，别混为一谈
  • 同类提醒：Codex 的本地与云端共享同一个 5 小时滚动窗口，云端不是白送的额外算力

选型心法

  • 按"人在不在场"分类，比按品牌分类有用得多：
    人在场 → 终端 / 编辑器；人不在场 → 云端异步；人在读 → 检索型
  • 默认用便宜档，卡住了再升 —— 而不是反过来
  • 官方实测参考：Claude Code 企业用户平均 $13 / 开发者 / 活跃日，约 $150–250 / 月，90% 的人每活跃日不到 $30
