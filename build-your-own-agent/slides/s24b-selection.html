再看用法：为什么我这样搭

每条尽量给个能查的数字撑着；纯凭感觉的我会明说。

Claude Code

主力
  • 闭环最完整：改完能跑、挂了能看见、能改回来

Codex

派活
  • 自己一个沙箱、自己一份 git：套路清楚的活派出去就不管，回来收 PR

Gemini Notebook

消化
  • 只照你给的材料答（source-grounded），方便核对它没编

Grok

探风向
  • 接 X 实时流：真实用户在骂什么 —— 官方博客不会告诉你
任务类型首选量化依据
深度重构 / 跑测试Claude Code + Opus 5 评测必须真跑测试
日常八成的活Claude Code + Sonnet 5 $2/$10 vs $5/$25，便宜 2.5 倍
同时跑一堆 / 批量 PRCodex 云端 + Terra $2/$12，价格正合适
批量粗筛 / 过日志GPT-5.6 Luna $0.20/$1.20，比同代旗舰便宜 25 倍
几个仓库一起翻子代理分头找 各看各的资料不互相带偏，代价是烧 token
啃长文档还要给出处Gemini Notebook 无量化对比，凭经验
私有化 / 数据不出境开放权重自建 短活差 0.5–7 分、价差 4.6–57 倍；长活还差 12–21 分

有句话得说清楚

  • Terminal-Bench 榜上 Claude Code 的默认配置不是第一：同一个 Opus 4.6，最好的 harness 76.4%，Claude Code 58.0%
  • 我选它不是因为分高，是因为能改的地方最多 —— 这是两回事

怎么挑，一句话

  • 按"你人在不在旁边"分，比看牌子管用：
    人守着 → 终端 / 编辑器；人走开 → 丢云上；人在读材料 → 检索型
  • 默认便宜档，卡住再升 —— 不是反过来

但这么切来切去，本身就很累

  • 四个工具、七种任务、每天在脑子里做一次路由 —— 这份心智负担没人给你算钱
  • 所以我想回到最开始那个定义：下一步由谁决定。把我这行里路子说得清、对错判得出的那一段，一次性写死成我自己的 agent
  • 挑哪一段？挑 ROI 最高的那段 —— 我每天都干、干得最烦、而且错了我一眼能看出来
