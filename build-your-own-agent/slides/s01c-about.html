关于这次分享

这不是产品宣讲，是一份工程读书笔记加一手代码取证

我自己在造一个 agent。造之前把这两年的公开工程实践系统啃了一遍 —— 与其让笔记烂在硬盘里，不如整理出来。

为什么讲这个

  • 市面上关于 agent 的内容，要么是概念科普，要么是产品广告。中间那层"到底怎么工程化"很少有人讲
  • 而这层恰恰是唯一你能自己掌控的部分 —— 模型你造不了，界面别人替你做了，中间那层只能自己写
  • 所以本场的所有断言都尽量挂上出处：官方博客、arXiv、以及直接打开源码看行号。凡是只在二手转述里见过的数字，一律不上页

你能带走什么

按投入产出排
  • 一套共同词汇 —— harness / context engineering / loop / graph / SKILL。以后跟人讨论 agent 不再各说各话
  • 一张决策表 —— 什么时候写 workflow、什么时候才轮到 agent、什么时候干脆别用
  • 一份选型依据 —— 主流 coding agent 的分野在哪，为什么"能不能改"比"多好用"更值钱
  • 几个能直接抄的工程模式 —— 会话树、渐进式披露、fork 的 tier 成本模型、生成与评判分离

我认为最值钱的三个点

  • 那场受控实验（第 13 页）—— 它把"harness 有没有用"从口水仗变成了可复现的数字
  • 相隔 24 小时的两篇对撞（第 22 页）—— 多智能体该不该做，两家顶尖团队公开打架，10 个月后一方改口。这段完整呈现比任何结论都有价值
  • FORK.md 的 tier 成本模型（第 31 页）—— 把"维护深度 fork"从英雄主义问题变成可优化的成本函数。这一页值得单独抄走
