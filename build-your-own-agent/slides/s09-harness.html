CH 3 · 原理 · L2–L6

Harness：包在模型外面的那台机器

模型只会"下一个词说什么"。让它真能干活的那一整套工程，就叫 harness —— pi 里真有个类就叫 AgentHarness。

开跑前先拍张快照

  • 这一轮用哪个模型、给哪些工具、什么 system prompt，开跑就锁死；你中途改设置，下一轮才生效 —— 免得跑到一半规则变了

留了 10 个口子让你插手

  • 往对话里塞一句话 / 换掉 system prompt / 改写上下文 / 拦下这次工具调用；最狠的一个：连"历史怎么压缩"都能你自己接管

什么时候写盘，定死了

  • 一条消息说完就落盘，每轮结束再统一存一个档；扩展正在忙就排队等它写完 —— 这样这份记录任何时候都能照着重放一遍

同一时刻只准干一件事

  • 五种状态：发呆 · 干活 · 压缩 · 总结分支 · 重试
  • 不在"发呆"就直接拒掉新请求。它不用一个 true/false 硬扛 —— 出事时你能一眼看出卡在哪一步
一句话 → 内核只管转圈：不存盘、不压缩、不管权限。这些全挂在外面那层。这条线画在哪，是造 agent 要做的第一个决定。
