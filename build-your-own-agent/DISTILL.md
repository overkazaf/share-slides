## 一、我的核心观点（重排后的 9 条）

> 现有的 thesis 页（P2）只有五句，全是「怎么做」，缺「是什么」和「怎么选」。下面这份是审计后的推荐清单。

| # | 一句话 | 在哪页被证 |
|---|---|---|
| 1 | 判断一个系统是不是 agent，只看下一步由**代码写死**、还是**模型现场决定**。 | P7 |
| 2 | harness 只值模型的四分之一 —— 但那四分之一是你唯一买不到、也唯一攥得住的。 | P13 |
| 3 | 上下文是**注意力预算**不是仓库：窗口装得下，不代表模型找得到。 | P18 |
| 4 | 别问该不该上 agent，要问**这一段决策能不能写死**；正解通常是 workflow 骨架 + 局部 agent。 | P7 / P22 |
| 5 | 让模型自评它只会自我吹捧 —— **生成与评判必须结构性地分开**。 | P23 / P25 |
| 6 | 你能给自己的领域**造出验证器**，agent 才真的进得来。 | P27 |
| 7 | 选型该问的不是谁更强，是**这层壳你能不能改、能不能拥有**。 | P29 / P35 |
| 8 | 护栏焊在**工具执行那一步和操作系统**上；靠提示词劝出来的安全都是剧场。 | P31 / P37 / P38 |
| 9 | 通用层已经被开源做完了，剩下那层**只有内行知道的约束**，只能内行自己焊。 | P39 |

**相对现有五句改了什么**

- 补进了全场缺失的**定义判据**（第 1 条）——原五句全是「怎么做」，听众只拍 P2 那一页会拿不到钥匙。
- 补进了**生成/评判分离**（第 5 条）——它在 P22 / P23 / P25 三处呼应，是全场被交叉验证次数最多、却没进 thesis 的一条。
- 补进了 CH5–CH7 的共同结论**「能不能改 > 谁更强」**（第 7 条）。
- 第 3 条改用自己的表述，不再是 Anthropic 原话的转述 + 无据的「绝大多数」。
- 第 9 条从引 pi 的 slogan 升级成一个**可证伪的判断**。

**开场句的建议**：把「模型决定能力上限，harness 决定你能兑现多少」保留为口号，但**主证据换掉**。
现在挂的 `6.7% → 68.3%` 是「最弱模型的极值」，NOTES 自己都称它是「全场最大的雷」。
更稳的说法：**「harness 只值模型的四分之一 —— 但差异化只可能长在那四分之一里」**，并把中位 5.39 分与最大 20.90 分一起念出来。

## 三、每章最被低估的点

### 开篇 + CH1
- **安全边界 = 你能 checkpoint 到哪一层。** 一手材料给的判据不是「有没有副作用」，是 *"can't be checkpointed"*。Cursor 只快照代码、Claude Code 把代码与对话拆成两个可独立回滚的维度、pi 让日志本身就是树 —— 这不是功能差异，是**可回滚边界的三个位置**。
- **判停不是布尔值，是枚举。** `ResultMessage.subtype` 就是现成的判停清单，且**只有 `success` 带 `result`**。再叠一层对照：OpenAI Agents SDK `DEFAULT_MAX_TURNS = 10`，Claude Agent SDK **默认无上限** —— 同一个「循环」，两家默认的安全姿态相反。
- **多智能体的收益方向与决策权谱系相反。** 2026 年的收敛结论是「写操作保持单线程，多出来的 agent 贡献判断力而不是动作」—— 在「交出多少决策权」这条轴上是**往左走**。

### CH2
- **范式转移的第一驱动力是「尺子」，不是能力、不是成本、不是工具链。** 能力在升而信心在降；成本反向（官方对照里完整 harness 贵 20 倍，人们照选）；Function Calling / MCP 是前提不是原因。真正的拐点是 2023 年尾 AgentBench / SWE-bench / GAIA 密集出现 —— **harness 能被单独测量之后，才从玄学变成学科**。
- **「harness 变重」和「harness 让路」是同期并行的**，不是先后。判据：harness 该管模型**拿不到**的东西（外部状态、权限边界、跨窗口持久化），不管模型**不会想**的东西。

### CH3 上
- **「预算不是仓库」是注意力力学的断言，不是窗口大小的断言。** 只加一个干扰项就低于 baseline；把 haystack 打乱**反而更好**；Lost in the Middle 的 U 型说明上下文里有盲区。所以 compaction 不只是删东西，**同时是在给幸存内容重新分配位置**。pi 用绝对阈值 16K 而非百分比，就是对这条的一行投票。
- **双层 while 买到的是「已收工」这个可重入状态。** 三种排队语义（steer / follow-up / next-turn）被分开建模；队列失败 `unshift` 回滚；`abort()` 把清掉的消息**还给调用方**。本质是：**模型的收工权和宿主的收工权被分在了不同层。**
- **会话树只让上下文维度的回退变便宜，对世界状态一个字没说。** replay 会重新触发副作用、bash 的 `rm/mv` 追不回来 —— 重试成本被**搬到了环境侧**，这才是 git-checkpoint / 沙箱存在的理由。

### CH3 下
- **subagent 的真收益是隔离不是并行。** 成本结构不支持「为了快」；BrowseComp 上 token 用量单独解释 80% 方差，而 15× 的 token **只有分窗口花才不劣化**；最决定性的一条：把并行完全拿掉收益仍在 —— Cognition 观察到 Claude Code 的子代理「从不并行、只回答问题、不写代码」，双方仍都认可它有效。**它是一台上下文压缩机，恰好长得像一个并发原语。**
- **渐进式披露里成本与准确率同向**（索引 100 : 全文 5000 ≈ 1:50，且只加一个干扰项就掉点），但代价是失败模式从「看得见的错」变成「**沉默的从未触发**」—— 全部赌注押在那一句 description 上。
- **Anthropic 与 Cognition 在「写代码不适合多 agent」上从无分歧**，所以 10 个月后收敛得很干净。判定三条件：读还是写 / 子任务之间有没有隐式设计决策耦合 / 单窗口装不装得下。

### CH4
- **「造验证器」有四条可操作的路径**：让 agent **够不着**裁判（隐藏 oracle）／让它必须留下**可抽查的证据链**／把有唯一正确答案的**确定性子步骤剥离**给程序／承认没有裁判，于是**只让它出候选**。
- **一个 agent 看得见的验证器，会退化成优化目标而不是真值信号。** 所以那条轴缺一个限定词：必须是**不可见、不可污染**的验证器。
- **矩阵少一条轴：失败成本。** 第四条红线（输入不可信）恰恰落在绿格里 —— 写代码完全满足两条轴，但输入源不可信时失败一点也不便宜。

### CH5
- **开源不预测存活，star 也不预测存活。** 2026 年的三个死者全是 Apache-2.0，其中一个有十万 star。
- **所以这张图不是排行榜，是保险单** —— 它回答的不是「谁会赢」，是「**它死的那天，你的定制有多少能跟着你走**」。存活因子：可接管性 / 自扩展性 / 下游依赖度 / 治理归属。
- **横轴「能不能改」可以量化，尺子在下一章**：扩展点的价值 = 它把多少 Tier-2 需求降级为 Tier-0。「加了很多 hook 但没人能只靠 hook 做完一件真事」= 扩展点失败。

### CH6
- **「不做清单」与「自扩展」不是并列，是因果。** 每一条 "No X" 都是把取舍成本从供应商转嫁给用户；只有当转嫁的代价低到**一次 prompt**，它才叫给你自由。**清单是支票，自扩展闭环是准备金。**
- **它与 CH4 第四条红线正面相撞，必须自己先说破**：pi 的 SECURITY.md 明写 prompt injection 不视为漏洞、"cannot be protected against"。答案不是「不用隔离」，是「**隔离不该长在应用层**」—— 因为半成品的隔离会被误认成安全边界。
- **FORK 最贵的成本项是漂移不是冲突**：「Conflicts you see; drift you don't」。分层依据是**与上游变更的正交性，不是改动大小** —— 1362 行住自有目录成本为零，3 行 turn-loop patch 每次都要重解。

### CH7
- **编排而非造模型，对在「主项买不到差异化」**：同 harness 换模型极差远大于同模型换 harness，而主项每几周免费涨一次。代价也要讲全：可归因性丧失、状态靠文件传、依赖两个周更 CLI 的登录态、两套权限叠加 —— 兜底 provider 是保险丝不是装饰。
- **七道坎里只有第 ④ 条能靠 prompt 缓解，其余六条必须落在 harness 层。** 一句话提炼：通用 coding 的约束是**给人看的**（规范、风格），逆向的约束是**给对手看的**（样本是敌人写的、结论要能被第三方证伪）—— 所以它必须是**执行前的闸门与执行后的轨迹**，不是执行中的劝说。
- **planner/executor 的分工依据是「角色需要什么样的沙箱」，不是跑分。** Grok 的价值在于训练家族独立 —— **失效模式不相关，复核才有信息量**。

## 四、两场对撞

全场有两场值得原样呈现的争论，维度不同，并列会很有力：

| | 争什么 | 页 |
|---|---|---|
| 第一场 | **控制流该不该写死** —— 运行的权威状态是 transcript 还是显式 state | P17（新增） |
| 第二场 | **要不要多个 agent** —— 并发写归属 | P23 |

**第一场的立场**：有便宜的 verifier 就用循环；verifier 只能是人或合规，就用图。
**图的真正作用不是让 agent 更聪明，是让人能在正确的位置插进去。**

最强反驳自己先说：verifier 的有无不是任务的固有属性，是**工程投入的函数**（官方原话就是 "encode verification as skills"）。
回应：造不出 verifier 的那一类，卡的不是「对不对」，是「准不准」—— Claude Code 说外部副作用 "can't be checkpointed, **which is why Claude asks before running**"，它没说「所以写个 verifier」，它说的是「**所以问人**」。

**这一页上必须承认的一条**：loop 与 graph 的同任务成本对照**公开数据不存在**。4× / 15× / 90.2% 是 agent-vs-chat 与 multi-vs-single 的口径，借来说事就是偷换。
