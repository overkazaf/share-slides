## P8 · 第 02 章 · 演进

**一句话主旨**：这一章只讲有日期锚点的历史，二手转述一律不上页。

**怎么讲**：

上一页我们的结论是"能写死的写死，写不死的才交给模型"。（停一下）那问题就来了 —— 这个结论不是天上掉下来的，它是这三四年里，一群人真金白银试错试出来的。所以第二章我们回头看一遍：它是怎么一步步走到今天的？

大家看左边，这是第二章，我们一共七章，进度条第二格亮着，右边这几页就是本章内容 —— 第 9 页讲 2022 到 2023，第 10 页讲 2024 年末到 2026，第 11 页讲这些节点背后分别是谁。

我想特别说一下左下角这段话，因为它是我做这一章的规矩。（放慢）这一章里出现的每一个日期，来源只有四类：arXiv 的 v1 提交日、GitHub 的首次 commit、npm 的发布时间戳、以及官方博客。凡是我只在别人的转述、别人的公众号、别人的 slide 里见过的数字，我全都没往上放。为什么要立这个规矩？因为 AI 这个领域的时间线特别容易被讲糊 —— 大家会把"某个东西火起来的时间"当成"它出现的时间"，差半年是常事。我自己前期就踩过这个坑，查着查着发现两个来源打架，最后只能回去翻机器时间戳。

所以你等会儿看到某个日期跟你记忆里不一样，很可能不是我错了，也不一定是你错了，而是我们俩数的是不同的口径。这种地方我会当场说明。

右下角这句是这一章的落点：读完你会知道，2023 年那场热潮为什么退了，以及 2025 年下半年真正的转折点发生在哪一天。

**别漏了说**：
- "只用可核查日期"这条规矩要当场立出来，它是后面所有页面的信誉基础，也是你敢在台上念数字的底气。
- 进度条要点一下：七章里的第二章，让听众心里有个位置感。
- 提前埋钩子："转折点发生在哪一天" —— 是"哪一天"，不是"哪一年"，这个措辞本身就是悬念。

**可能被问**：
- Q：为什么不讲国内的进展？
  A：不是有意略过，是我这次的取证方式（arXiv / GitHub / npm / 官方博客）对国内很多工作覆盖不全，硬讲我怕讲错口径。这块我没系统查过，会后可以单独聊。
- Q：这章会讲模型能力本身的演进吗？
  A：基本不讲。这一章的主线是"模型外面那层壳"怎么演进的，模型本身只作为时间锚点出现（比如 GPT-4 发布日）。

**过渡到下一页**：那我们从头开始 —— 第一幕，2022 到 2023，一年半时间里，行业先学会了会推理，再学会了会动手，然后一头撞在墙上。

## P9 · 演进 I（2022 – 2023）：从会推理，到会动手，然后撞墙

**一句话主旨**：第一幕赌的是"模型够强 + prompt 够好"，赌输了，但输得很有价值。

**怎么讲**：

刚才说从头开始，这一页就是"头"。整页三个盒子，从左到右是时间顺序，中间有箭头连着，我们一个一个看。

左边这个青色盒子是 2022 年，标题我写的是"先解决想清楚这件事"。里面五个点：一月的 Chain-of-Thought 预印本，让模型把中间步骤说出来；五月的 MRKL，第一次认真讨论模型加外部工具的路由。然后是这个大一号的点 —— 2022 年 10 月 6 号，ReAct 预印本。（重读日期）这篇是把"推理"和"行动"交替起来，想一步、做一步、看结果、再想。今天你打开任何一个 agent 的主循环，骨架都是这个。十八天后，10 月 24 号，LangChain 第一次提交。再过一个月，11 月 30 号，ChatGPT 发布。下面这行是我的总结：这一年回答的问题是，模型能不能想清楚，并且说出"我要用哪个工具"。注意 —— 只是"说出"，还没到真去用。

中间红色这个盒子，2023 年春天，三个月。3 月 14 号 GPT-4 发布，两天后，3 月 16 号 AutoGPT 第一次提交 —— 它的 commit message 就三个词，"Initial prompt."（停顿）我觉得这个细节很能说明当时的气氛：大家真的相信，一段足够好的 prompt 就够了。然后 3 月 23 号 ChatGPT Plugins、3 月 28 号 BabyAGI 的前身博文、4 月 7 号斯坦福小镇。到 4 月 22 号，这个黄点，星标破十万 —— 但同一时期，唱衰的声音也开始出来了。盒子底下这行是它留给后来所有人的作业：它跑得动，但停不下来、记不住、也说不清这次为什么成了。

右边绿色盒子是 2023 年中后段，"差距被量化了"。5 月的 Voyager 做终身学习式技能库；6 月 13 号 Function Calling 发布 —— 这是工具调用第一次被标准化成 API 能力，从此不用再靠 prompt 求模型输出合法 JSON。11 月 21 号 GAIA 基准发布，就是这个红框里的两个数（慢念）：人类 92%，GPT-4 加插件 15%。这是 GAIA 论文自己的口径，不是我测的。这个差距一摆出来，行业才第一次公开承认：不是 prompt 不够好。

底下两行是这一幕的信念和教训，教训那句请记住：自主性本身不稀缺，可控性、可观测性、可复现性才稀缺 —— 而这三样都不在模型里，在你写的那层壳里。

**别漏了说**：
- 92% vs 15% 一定要说清口径：GAIA 基准发布时的数字，人类对照组 vs GPT-4 加插件，不是今天的水平，也不是我复现的。
- "Initial prompt." 这个 commit message 是页面上的原文，讲它是为了还原当时的信念，不是嘲笑。
- 左下角那行小字要点一下：star 数据来自 Wayback Machine 对仓库页面历史快照的解析，不是引别人的图。
- 三个盒子的颜色是有意的：青色=想清楚，红色=撞墙，绿色=开始有接口，别让听众自己找规律。

**可能被问**：
- Q：AutoGPT 到底是 3 月 16 号还是 3 月 30 号？后面人物谱那页写的是 30 号。
  A：问得好，这两页确实是两个口径 —— 这页写的是 GitHub 首次 commit，人物谱那张卡片上标的是 2023-03-30。我当时是从不同来源分别取的，没在页面上标清楚，这是我的疏漏。准确的对应关系我会后核对了发给大家。
- Q：ReAct 之前难道没人做工具调用吗？
  A：有，页面上这条 MRKL（2022-05-01）就是。ReAct 的贡献不是"能用工具"，是"想和做交替进行"这个循环结构。
- Q：十万 star 为什么反而是唱衰的起点？
  A：页面上我只放了"同期开始唱衰"这个事实，没有放具体的批评来源。我的理解是跑起来之后大家发现它停不下来、烧钱，但这属于我的解读，不是页面上的论据。

**过渡到下一页**：所以第一幕结束时，问题清单已经很清楚了 —— 停不下来、记不住、说不清。接下来两年，行业就是在还这三笔债，而还债的方式，跟大家当初想的完全不一样。

## P10 · 演进 II（2024 末 – 2026）：范式转移，harness 成为一等公民

**一句话主旨**：真正的转折点不是某个模型发布，是 2025-09-29 那一天。

**怎么讲**：

上一页留了三笔债。这一页是还债过程，四幕，从左到右。

第一个灰色盒子，第二幕，2024 年 12 月 19 号，《Building Effective AI Agents》。它做的事看起来很朴素：把 workflow —— 预定义代码路径 —— 和 agent —— 模型自主决定流程 —— 明确分开，给五种模式起了名字。但盒子里这句才是当时最刺耳的：行业第一次公开说，"大多数场景你不需要 agent"。这一幕的转向写在最下面：从追求自主性，转向追求可控性。

第二个橙色盒子，第三幕，接工具变成了协议问题。2024 年 11 月 25 号 MCP 开源，2025 年 3 月 26 号 OpenAI 采纳，4 月 9 号 Google 采纳。这三个日期连起来才有意义 —— 一个厂商发的东西，被竞争对手接受了，它才算协议。中间这行是 N 乘 M 的定制集成变成 1 乘 N 的协议。底下这句我很喜欢：能力边界的定义变了，从"模型知道什么"，变成"模型能连上什么"。

（放慢，指黄框）第三个盒子，注意它的边框是加粗的，因为这是本章的转折点。2025 年 9 月 29 号，同一天，做了三件事：一，发《Effective context engineering》；二，Claude Code SDK 改名叫 Claude Agent SDK —— 这不是改名，是承认这套东西不只服务写代码；三，Claude Code 2.0 上线检查点和回退。半个月后，10 月 16 号 Agent Skills 发布。这三件事合起来是一个宣言：能力上限不再主要由模型决定，而由包裹模型的那层工程决定。下面那句是 SDK 的原话 —— "给你的 agent 一台电脑"。

最右边紫色，第五幕，harness 自己被拆开卖了：长任务架构化、规划生成评判分离、脑手记忆三层解耦、单会话编排数十到数百 agent。核心洞察在下面：让模型自评会自我吹捧，所以必须结构性地分离生成和评判。

最下面这排是五个被替换掉的旧信念，红的是旧的，绿的是新的，灰色是替换发生的时间点。这排你们回头看 PDF 就行，我不念了。

**别漏了说**：
- 9-29 那天的三件事必须一件一件点，尤其"SDK 改名"这件最容易被当成琐事跳过 —— 改名恰恰是定位变化的证据。
- 五个信念替换那排，至少挑一条展开（比如"窗口越大越好 → 注意力预算"），否则听众只看到一堆彩色小字。
- takeaway 里的"第六幕"是本页最诚实的部分，务必讲：2025 年 10 月 30 号，Claude Code 2.0.30 主动弃用了自带的 output styles，把控制权交回用户和模型。这跟前面"harness 越来越重"是反向的信号，两边都要讲 —— 我个人倾向是随着模型变强，harness 应该主动瘦身，只保留权限、沙箱、状态持久化、验证回路、并行调度这几样模型确实做不好的，但这只是倾向，不是结论。
- 底部小字的取证方式（npm registry / PyPI / GitHub API 机器时间戳 + 官方博客交叉验证）值得再强调一次。

**可能被问**：
- Q：把一天定为"转折点"是不是太戏剧化了？同一天发三个东西，本来就是发布节奏安排。
  A：这个质疑我接受。严格说这一天是"信号最集中的一天"，不是因果意义上的转折。我选它是因为三件事指向同一个主张，而不是因为它们撞在同一天。
- Q：这几幕是不是全是 Anthropic 视角？
  A：是的，这页的日期锚点确实集中在 Anthropic 的博客和 CHANGELOG，因为这条线的文档最完整、最好核。别的厂商同期的工作我没有等量取证，这是本页的偏差，我承认。
- Q：2026 年那几条（3 月、4 月、5 月）具体是谁做的？
  A：页面上我只留了架构主张，没留出处名，因为部分来源我只找到二手转述，没敢往上放。这几条属于"方向可信、细节待补"，会后我补一份带链接的清单。

**过渡到下一页**：讲了两页日期，其实每一个日期背后都是具体的人。下一页我们把这些名字摆出来，其中有两个人，可能跟你想的不太一样。

## P11 · 关键人物谱：每个节点背后是谁

**一句话主旨**：本场的两个主角，出身都不在 AI 圈。

**上一页收尾承接**：日期背后是人 —— 现在看看是哪些人。

**怎么讲**：

这页是两排卡片。上面一排是奠基期，2022 到 2024；下面一排是工程化，2024 到 2026，同时也是本场的样本来源。

上排从左到右：Shunyu Yao，姚顺雨，ReAct 的作者，arXiv v1 是 2022 年 10 月 6 号 —— 就是上上页那个大点；他后来还参与了 SWE-bench、SWE-agent、τ-bench，也就是说，提出循环的人，后来去做了衡量循环的尺子。第二位 Harrison Chase，LangChain 的联合创始人，2022 年 10 月 24 号第一次提交，他真正的贡献是把"把 LLM 和工具接起来"变成了一个基础设施品类。第三位 Toran B. Richards，AutoGPT。卡片上我写得很直白：他证明了全自主循环能跑，也证明了它会原地打转、会烧钱、会跑飞。（停一下）红字这句是我想说的 —— 这次"失败"极其有价值，它定义了后来所有人要解决的问题。第四位 Yohei Nakajima，BabyAGI，他的身份是一位投资人，一个投资人写的 demo，成了那一年最好的教材。第五位 Scott Wu，Devin，第一个把 agent 当"AI 软件工程师"卖的产品 —— 卡片下面那行也别跳过：评测口径的争议也是从这里开始的，这行业从此学会了看清楚分母。

下排。Anthropic 工程团队，《Building Effective Agents》那条主线。Paul Gauthier，Aider，仓库 2023 年 5 月 9 号 —— 仓库地图、自动 commit、编辑格式的实证调优，今天所有 CLI coding agent 身上都有它的影子。

然后请看这两张加粗边框的卡片。Mario Zechner，网名 badlogic，他的老本行是 libGDX —— 一个做了十几年的游戏引擎。他写的 pi，仓库 2025 年 8 月 9 号，MIT 协议。这两个数我念慢一点：八万一千五百四十五颗星，一万零六十八个 fork，采集时间 2026 年 8 月 1 号，用 GitHub API 拉的，就是今天。旁边这位 Armin Ronacher，网名 mitsuhiko，写 Flask 的那个人，现在是 pi 的第二号提交者。最右边 Can Bölük，写 NoVmp、ByePg 的逆向工程师 —— 写 VMProtect 去虚拟化器的人，把 pi fork 成了 oh-my-pi。这条红线记住，第七章要用。

（指底部）所以这一页真正的落点在这儿：这不是 AI 圈的产品，是系统工程师圈的产品。（停）本场的两个主角，出身都不在 AI 圈。

**别漏了说**：
- 81,545 星 / 10,068 fork 的口径要说全：GitHub API 实测，采集于 2026-08-01，是当天快照，不是历史峰值。
