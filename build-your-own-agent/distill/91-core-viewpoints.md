# 「我的核心观点」审计与重排 · 37 页全场

> 口径约定：本文严格区分三类陈述——
> **[断言]** = 作者自己的判断，页面上没有、也不可能有外部证据；
> **[一手]** = 有官方页 / arXiv / 源码行号 / API 时间戳支撑；
> **[转述]** = 引自第三方博客、内部评测、项目自测，作者本人已声明未复现。

## 一、现有五句的审计

### ① 模型决定能力上限，harness 决定你能兑现多少（→ P13）

**它到底在主张什么**
表面是"两者都重要"，实际主张是一条投资建议：**你唯一值得投入工程的，是 harness 那一层**。

**证据够不够硬**
证据是双向的，而且作者自己在 NOTES.md 里把 P13 标成「全场最大的雷」：
- 正向：16 模型 × 180 任务、只换 edit format，Grok Code Fast 1 从 6.7% → 68.3%，全体 +15pp。**[转述]** —— Can Bölük《The Harness Problem》，作者明说"我核过原文，但没有复跑"。而且原作者自己写了「越弱的模型收益越大」。
- 反向：Terminal-Bench 官方榜 22 个模型换 harness，**中位数只挪 5.39 分**；同一 harness 换模型极差 70.7pp。**[一手]**

所以页面上那句话跟页面上的数字**方向一致但量级不一致**。thesis 页只放了 6.7→68.3，把补丁全部推给了 P13。这是五句里**证据与措辞落差最大的一句**。

**有没有更锋利的表述**
作者自己在 P13 讲稿里说得比 thesis 页好得多：
> 「模型是主项，harness 是不可忽略的次项，大约是模型效应的四分之一量级。**但主项买不到差异化，因为大家用的是同几个模型；次项才是你能自己攥在手里的那部分。**」

锋利版：**「harness 只值模型的四分之一 —— 但那四分之一是你唯一买不到、也唯一攥得住的。」**
这版把"重要性"换成了"可占有性"，反驳不了，因为它不再声称量级。

**会被怎么反驳**
- "6.7→68.3 是标题党"—— 会中。作者的答案已经准备好了（NOTES 四之一），但答案在 P13，不在 P2。
- "既然模型是主项，那我该多买模型而不是造 harness"—— 现有措辞挡不住这一击，锋利版能挡。
- 最扎心的补充证据反而在 NOTES 里没上 thesis：Gemini 3 Pro 套通用 harness 73.93%，套自家 Gemini CLI 65.84%。**这条比 6.7→68.3 更适合放在开场**，因为它是官方榜、一手、且反直觉。

**结论：措辞需要改，是五句里最该动的一句。**

### ② 上下文是预算，不是仓库（→ P18）

**主张**：注意力是被摊薄的有限资源，"装得下"不等于"找得到"，所有 context engineering 都是这一句的推论。

**证据**：五句里**最硬的一句**。
- 厂商一手数据：同一个 Gemini 3.6 Flash，128k 窗口召回 91.8 → 1M 窗口掉到 54.0。**[一手，Google 官方模型页]** 作者在 P12 讲稿里专门提醒"这是官方自己写的，不是第三方测的，分量完全不同"。
- n² 那段是 Anthropic 官方博客的**直觉解释**，作者自己标了"别当定理用"。**[转述/官方表述]**

**更锋利的表述**：现有的已经很好，但缺了后半句的杀伤力。
建议：**「上下文是注意力预算不是仓库 —— 窗口装得下，不代表模型找得到。」**
把"预算"这个隐喻和"91.8 → 54.0"这个事实用一句话锁死。

**会被怎么反驳**：
- "长上下文模型一直在进步，这条会过期" —— 能答：过期的是数字，不是机制；而且退化数据恰恰来自最新一代模型的官方页。
- "那百万窗口没意义了？" —— P18 Q&A 已备。

**结论：保留，微调后半句。**

### ③ 能写死的就别让模型猜（→ P22）

**主张**：绝大多数"我需要一个 agent"其实是五种 workflow 模式之一。

**问题：这句严格说不是作者的观点，是 Anthropic 的观点。**
五种模式、"大多数场景你不需要 agent"，全部出自《Building Effective AI Agents》（2024-12-19），作者在 P22 明说"这一页是词汇表，不是论证"。放在「我的核心观点」页上，属于**借来的锋利**。

**作者自己的版本在 P7，比这句强**：
> 「不要问"我该不该上 agent"，要问"**这一段决策我能不能写死**"。绝大多数生产系统的正解是 **workflow 骨架 + 局部 agent**，不是全盘自主。」

后半句"workflow 骨架 + 局部 agent"是作者自己的归纳，且在 P7 / P22 / P29（Claude Code 内部也有大量写死段落）三处呼应。

**证据强度**：分类学有一手出处；"绝大多数"这个量词**没有任何数据支撑**，是 [断言]。作者在 P7 Q&A 里也承认"我没有一个能量化的判据，这是经验活"。

**会被怎么反驳**：
- "2024 年划给 agent 的场景现在 workflow 也能做，反过来也成立，边界一直在滑" —— 作者自己在 P22 Q&A 里已经承认这点，等于自己削弱了这句的时效性。
- "绝大多数是多少？" —— 无法回答，只能承认是经验。

**结论：保留论点，换成 P7 的表述，把"绝大多数"的量词负担卸掉。**

### ④ 你能给自己的领域造出验证器，agent 才真的能进来（→ P27）

**主张**：coding 先落地的真实原因是编译器和测试天然是验证器；没有验证器的领域，agent 只会自信地胡说。

**证据**：**零外部证据，纯 [断言]。** 四象限是作者自己归纳的（页脚写明"不是谁的官方分类"），P27 Q&A 里作者主动说："没有量化数据支持甜点区这个划分……我不想假装它有数据。"

**但这是五句里最原创、最可迁移的一句。** 它同时是全场的结构性支点：
- 它解释了 P27 的红线区（既枚举不出路径，又验证不了对错）；
- 它解释了 P37 第⑤坎（逆向必须可复现 → 92% vs 37% 的记忆落差）；
- 它解释了 P38 为什么 re-agent 的交付物是"可被第二个人原样重放的分析轨迹"。

所以它的合法性不来自数据，来自**它在三章之间成立**。这是可以在台上明说的：「这条没有数据，它是一个框架；它的价值在于它在后面三章都对得上。」

**更锋利的表述**：现有版本 22 字已经很好。可以更狠：
**「没有验证器的领域，agent 出错的时候和做对的时候长得一模一样。」**（P27 的情绪高点原句）
但这句是"警告"，不是"判据"。建议主句仍用验证器版本，警告句留给 P27 现场。

**会被怎么反驳**：
- "验证器不保证正确，只保证没崩" —— 作者 P27 Q&A 已备答（"降低搜索成本，不替你做 code review"）。
- "创意方向被划进红线太绝对" —— 已备答（发散工具 ok，拍板不 ok）。

**结论：保留，是五句里最值钱的一句。**

### ⑤ 模型是租来的，工具是现成的 —— 但那层壳只能自己焊（→ P31 / P39）

**主张**：为什么值得自己造。

**问题：这句的证据位挂的是 pi 官网的 slogan。**
"There are many agent harnesses but this one is yours" 是 **别人的口号**，不是论据。放在结论页上，等于用一句广告词收尾一条价值主张。

**作者自己更硬的版本在 P39 收尾**：
> 「这不是 AI 让人人都能创业的鸡汤，是个具体判断 —— **agent 的通用层已经被做完并开源了，剩下的是各行各业那层只有内行才知道的约束，而那层只能内行自己焊。**」

这一版是可证伪的判断，而且下面挂着四条硬支撑（P39）：模型几美元/百万 token 不用训；壳 2,379 行 17 文件（本地实测）；领域知识靠年头攒；窄到大厂看不上。**[一手，本地实测 + 官方定价]**

**会被怎么反驳**：
- "大厂真做不了这层吗" —— 作者 P39 Q&A 自己承认："大厂做得了，只是不划算……我唯一的护城河是我比他们更懂流程细节，**这个护城河不宽**。" 这是全场最诚实、也最脆弱的一处。
- "2,379 行能干活吗" —— 作者承认现在是原型不是成品。

**结论：论点保留，但表述必须从"引用 slogan"升级成"作者自己的判断"。**

### 五句整体的三个结构性问题

1. **五句都在讲"怎么做/为什么做"，没有一句在讲"是什么"。** 全场 CH1 的判据（下一步由谁决定）是后面 30 页的前提，却完全没进结论页。听众如果只拍这一页，拿不到那把钥匙。
2. **五句里有两句（③⑤）主要是转述别人的话。** 而作者自己反复讲、跨三章交叉验证的几条（生成与评判分离、上下文隔离、能不能改）一条都没进。
3. **没有一句涉及安全/边界的结构性主张**，而这恰恰是全场出现频次最高的一个观点（P6 / P31 / P37 / P38 四页）。

## 二、遗漏的核心观点（按证据强度排序）

### A. 控制流归属之争：判断 agent 只看一条 —— 下一步由代码写死，还是模型现场决定

- **一句话主张**：agent 不是能力问题，是**决策权归属**问题；把"是不是 agent"当是非题问错了，该问"这一段的决策权交出去了多少"。
- **支撑页**：P6（三条判据：能动手、能循环、能看见，缺一退化）、P7（决策权谱系五格 + 渐变条，坐标轴就是"谁决定下一步"）。分类口径来自 Anthropic《Building Effective Agents》**[一手]**，但"这是唯一判据"和"五个盒子只是连续谱上的采样点"是作者的 **[断言]**。
- **反方立场**：学术界的 agent 定义远比这宽（作者 P5 Q&A 自己承认"不统一，我采用的是 Anthropic 那套"）；也有人会说决策权是渐变的，用它做判据等于没判据。作者的答案就是"所以我给的是尺子不是分类"。
- **为什么该进**：它是后面所有页的前提。没有它，P22「能写死就别猜」缺一个坐标系。

### B. 会话树是可执行状态，不是历史记录

- **一句话主张**：只追加、不改写的 JSONL 树让"回退、分叉、换模型、重放"变成一等能力；session 不是日志，是你能重新执行的状态。
- **支撑页**：P16（append-only、parentId、旧分支不删只是不在路径上、三种分叉语义、被放弃分支压成摘要注入）**[一手，pi 源码/文档]**；P14（持久化排队等存档点，"记录才可重放"）；P25（压缩本身也是树上一个节点）；P31（可 fork/resume/回到任意一步换条路）；P38（re-agent 的只追加 JSONL 是为了可复现）。
- **额外时代锚点**：Earendil《The Session You Cannot Take With You》2026-07-30，HN 733 分 —— provider 正在用加密 reasoning token 把 session 锁死（R07 §5.3）。**这条讲稿里没用，是可以加的最新弹药。**
- **反方立场**："只增不减磁盘会爆"（作者 P16 Q&A 承认没实测）；"被放弃的分支摘要注入会把新分支带偏"（作者自己承认有这个风险，认为应该可配）。
- **为什么该进**：它是全场唯一一条"工程模式"级别的可抄结论，而且是 P39「可复现的分析轨迹」的直接来源。

### C. 子代理的真收益是上下文隔离，不是并行；写操作必须保持单线程

- **一句话主张**：多加一个 agent 该贡献判断力，不该贡献动作。
- **支撑页**：P7（05 格明说"主要收益是上下文隔离，不是人多力量大"）；P23（Anthropic 自报 90.2% + **15× token 代价**，两个数出自同一篇；Cognition 的 Flappy Bird 风格漂移；10 个月后同一作者收敛到 "writes stay single-threaded, additional agents contribute intelligence rather than actions"）**[转述，作者明说 90.2% 是自测自己"我不完全信"]**；P24（"让 subagent 并行写文件基本等于灾难"）；P35（子代理扇出的依据是官方定性口径，token 放大倍数作者承认没数）；P38（planner/executor/Grok 复核就是这条的实现）。
- **反方立场**：Cognition 原始立场「别搞多智能体」；LangChain 的裁决（"是 context engineering 问题，不是架构问题"）—— 作者自己指出 LangChain 有立场，因为他们卖编排框架。
- **为什么该进**：五页交叉引用，且是 re-agent 架构的直接依据。现有五句完全没覆盖多 agent。

### D. 生成与评判必须结构性分离 —— 让模型自评，它会自我吹捧

- **一句话主张**：评审方**不共享**生成方的上下文，效果反而更好，因为它没被主线的叙事说服过。
- **支撑页**：P22（evaluator-optimizer，作者标注"2026 年的实践发现"是他自己加的注，不是 2024 原文）；P23（Cognition 2026-04-22 自己说"这反直觉"）；P25（advisor/watchdog 只读增量做同行评审）；P10（第五幕："让模型自评会自我吹捧，所以必须结构性地分离生成和评判"）；P38（Grok 只做交叉复核）。
- **作者自己的定性**：P25 讲稿原话——「这一条在这一整章出现了三次……**这是全章唯一被反复交叉验证的结论**」。
- **反方立场**：不共享上下文的评审也会误判（缺背景就容易挑无关的刺）；两套都上意味着两份成本，作者自己建议小项目只上事后评审。
- **为什么该进**：**这是作者亲口认定的"全章唯一被反复交叉验证的结论"，却没进结论页。这是最明显的一处遗漏。**

### E. 选型该问的不是"谁更强"，是"这层壳你能不能改、能不能拥有"

- **一句话主张**：分数三个月过期，架构选择不会；把赌注押在你能改的那部分，别押在别人的路线图上。
- **支撑页**：P28（本章承诺，作者原话"本场我最想推的一个选型观念"）；P29（空象限：**没有"极简 + 闭源"的产品，因为闭源没有做极简的商业动机**——这是作者自己的商业推理 **[断言]**，但极有说服力；以及"有产品停运了、有免费档停服了、有产品改名换东家了"**[作者本次核实所得]**）；P35（**Terminal-Bench 官方榜同一个 Opus 4.6，最好的 harness 76.4%，Claude Code 58.0%；我选它不是因为跑分最高，是因为我能把规范焊进去** **[一手]**）；P11（pi 的 IP 归 Earendil，承诺 MIT ≠ 法律约束）。
- **反方立场**：可修改性对绝大多数团队是负资产（R07 §8.2 evilduck："维护插件不免费，它花 token、时间和注意力，而且你几乎肯定在重造一个别人造得更好的轮子"）；企业采购根本不看"能不能改"，看的是 SLA 和合规。
- **为什么该进**：它是 CH5 + CH6 + CH7 三章的共同结论，且 P35 那组 76.4 / 58.0 是全场最能证明"跑分 ≠ 该选"的一手数字。

### F. 护栏要焊在结构上 —— 焊在工具执行那一步和操作系统边界上，而不是写进提示词

- **一句话主张**：应用层的确认弹窗是安全剧场；能被提示词劝住的东西，也能被提示词劝反。
- **支撑页**：P6（"护栏装在③环境执行这一段，装在别处都晚了"）；P31（No permission popups → "把安全边界交给操作系统，而不是假装在应用层解决"；pi 官方文档原话 "A partial in-process sandbox would be easy to misunderstand as a security boundary" **[一手，docs/security.md:31-35]**）；P37 第⑥坎（**样本本身就是攻击面** —— arXiv 2605.30667 的 PoC：在可执行文件的只读段塞一段不影响功能的字符串，就能给分析它的 LLM 下指令；八个前沿模型的拒绝率约 0.86% **[转述，作者未复现，且 arXiv 编号 NOTES 标了"上台前复核"]**）；P38（策略闸门：读限工作区 / 写要 --write / 联网要 --allow-network / 敏感路径要 --allow-sensitive，"不是靠提示词劝模型，是靠开关"）。
- **反方立场**：R07 §4.2 减分派 esafak——"agent 必须跟外界交互，你 sandbox 不了一切，把配置推给沙箱是比 harness 在恰当时机问你更差的 UX"；以及作者自己的让步："现实中大量用户就是裸跑在开发机上，**企业环境里我不会推荐这么用**"。
- **为什么该进**：全场出现频次最高（四页），且是 re-agent 唯一一条红色箭头的设计依据。

### G. 通用 coding agent 干不了逆向，是结构性的 —— 不是效果差一点，是几条基本假设不成立

- **一句话主张**：通用 agent 默认「代码可读、工具无状态、输入可信、结果可复述」，逆向这四条全不成立。
- **支撑页**：P37 七道坎。作者自己交代了口径：**①②③是我自己踩的，④⑤⑥是论文和公开评测归纳的，⑦是领域共识加体感**（P37 Q&A）。硬数字：同一模型生成题 92% vs 公开题约 37%（CrackMeBench，**[转述]**）；混淆下 REFORGE 的高置信 ground truth 产出率 87.2% → 65.9%（R09 B2-7）；LLM 连 0x41424344 转 ASCII 都不能自己算（ida-pro-mcp README **[一手]**）。
- **反方立场**：模型在变强，这些坎是当期快照不是结构；"最后一公里工具"这个定位本身也在往前滑。作者的答案（P37 Q&A）："例子会过时，机制不会。"
- **为什么该进**：它是全场 CH7 成立的唯一理由，也是"造垂直 agent"这件事的普适模板 —— 每个行业都该问自己"通用 agent 的哪几条假设在我这不成立"。

### H. 维护深度 fork 是可度量的成本函数，不是英雄主义 —— 最便宜的分歧是被消除掉的分歧

- **一句话主张**：挑能干成事的最低那一档（pick the lowest tier that works）；Tier 2 深改核心 → Tier 1 一行缝隙（全仓硬配额 4 个坐标）→ Tier 0 零冲突；再把那行缝隙提 PR 给上游，你的核心补丁就永远消失了。
- **支撑页**：P32（FORK.md，作者原话"**我认为这整场分享里最可迁移的一个工程方法**，跟 AI 一点关系都没有"）；P38（"用 FORK.md 的话说：能放 Tier 0 的，一律不进核心"）；P3（列为最值钱的三个点之一）。**[一手，oh-my-pi FORK.md + 本地 v16.3.12 实测行数]**
- **反方立场**：作者自己承认"我没有实测过它的同步频率和冲突率，属于一手文档、二手结论"；"Tier 1 为什么是 4 个"没有推导过程。
- **该不该进结论页**：**这条是最好的"方法"，但不是最好的"观点"。** 它跟全场主线（造自己的 harness）的耦合度低于 A–G。建议留在 P32 做单页高光，不进核心观点清单 —— 但可以在 P3「最值钱的三个点」里保留。

### 被测试后剔除的候选

- **「fork 比上游贡献更便宜」**——**材料不支持，而且方向是反的**。FORK.md 的原话是"最便宜的分歧是被消除掉的分歧"，即**上游合并优于长期 fork**；三层 tier 的整个目的就是把改动往上游推或往 Tier 0 挪。若这样表述会当场被熟悉 FORK.md 的人指出讲反了。
- **「harness 应该随模型变强主动瘦身」**——有支撑（P10 别漏了说：2025-10-30 Claude Code 2.0.30 弃用自带 output styles，把控制权交回用户和模型），但作者自己明确标注"**这只是倾向，不是结论**"。不适合放进"我的核心观点"。
- **「记忆要按三个尺度分开设计」**（P25 左半屏）——成立且实用，但是层级低于 A–G 的实现建议，不是全场主张。

## 四、哪几句最可能被挑刺（Top 3）

### 挑刺 #1 —— 02「harness 只值模型的四分之一」

**反方**：「四分之一是怎么算出来的？Terminal-Bench 上那些 harness 根本不是控制变量，框架、工具集、运行预算全不一样。而且中位数才 5.39 分，你凭什么说它值得投入一整场分享？」

**最佳答法**（作者已备，P13 Q&A）：
> 「你说得对，那不是严格控制变量，所以我只说'约四分之一量级'，不说精确倍数 —— 这一点我在页面上就承认了。至于 5.39 分值不值：**在这个榜的头部区间，5 分足以差出十几个名次，而它是你唯一能自己动的变量。我没说 harness 比模型重要，我说的是它是你能攥住的那部分。**」

**加分弹药**（目前只在 NOTES 里，建议搬上台）：Gemini 3 Pro 套通用 harness 73.93%，套 Google 自家 Gemini CLI 65.84% —— 自家工具输给通用工具 8 分。**这是官方榜的一手数据，比 6.7→68.3 更难反驳。**

### 挑刺 #2 —— 08「造出验证器 agent 才进得来」

**反方**：「这条完全没有数据。四象限是你自己画的，甜点区是你自己定的。凭什么让我们抄一个没有实验支撑的框架？而且验证器只能证明'没崩'，证明不了'对'——测试全绿的错代码你见得还少吗？」

**最佳答法**：
> 「**没有数据，这一点我在 P27 就说了，我不想假装它有。**它是一个归纳框架，不是实验结论。它的合法性来自另一件事：**它在后面三章都对得上** —— P37 逆向那七道坎里最要命的第⑤条就是'结果必须可复现'，P38 re-agent 的交付物因此定成了'可被第二个人原样重放的轨迹'。一个框架如果在三个不相干的地方都能预测到我遇到的问题，我就先用着。
> 至于第二问：对，**验证器只降低搜索成本，不替你做 code review**。甜点区的意思是'值得试'，不是'可以不看'。」

### 挑刺 #3 —— 10「通用层已经做完了，剩下的只能内行自己焊」

**反方**：「这就是护城河幻觉。大厂真想做，一个季度就把你这行吃掉了。而且你自己都说 re-agent 现在 2,379 行、IDA 和 Ghidra 还没接进来 —— 拿一个原型来论证'一个人就能干'，样本量是 1，还没跑完。」

**最佳答法**（作者 P39 Q&A 已有雏形，但要压得更实）：
> 「**大厂做得了，只是不划算 —— 这个市场对他们太窄。如果哪天他们决定做，我唯一的护城河就是我比他们更懂这行的流程细节，而这个护城河不宽。**我不打算把它说成壁垒。
> 关于样本量：对，n=1，而且是个原型。所以我今天讲的不是'我成功了'，是**四条可核查的前提** —— 模型几美元一百万 token 不用训、壳两千多行一个人几周能写完、领域知识靠年头攒得出来、窄到大厂看不上的市场对一个人足够大。**这四条如果你那行也成立，结论就成立；有一条不成立，就别信我。**」

> 另有两处次级风险，答案已在讲稿里，不列入 Top 3：
> - 05「生成与评判分离」会被问"评审方不共享上下文，不会因为缺背景而误判吗"—— 答：会，所以它治的是"被主线叙事说服"这一类错，不是全部错。

## 五、一个更锋利的开场主张

### 结论：**保留这条主张的位置，但换掉这条主张的措辞。**

现有开场：
> 「模型决定能力上限，harness 决定你能兑现多少」

**为什么不能原样留**
1. **它承诺了一个页面上数字撑不住的对称性。** "决定能力上限 / 决定兑现多少"读起来是 50:50，但作者自己在 P13 讲的是 4:1，NOTES 里更是把这页标成"全场最大的雷"。**开场页比正文页更乐观，是所有演讲最危险的结构。**
2. **它可以被一句话卸掉**："那我多花钱买模型不就完了？" 现有措辞没有回答这个问题的能力。
3. **"兑现"是个含糊词。** 兑现多少？无法证伪的措辞在结论先行页上是负资产 —— 而这场分享的全部可信度都建立在"可核查"三个字上。

**为什么不能换掉这条主张本身**
它是全场的因果起点：只有先承认 harness 值得投入，后面 24 页的技术点才有理由存在。而且它是唯一一条有**受控实验 + 官方榜双向证据**的主张。位置必须保住。

### 推荐替换句

> **「模型你买得到，harness 买不到 —— 它只值模型的四分之一，但差异化只可能长在那四分之一里。」**（38 字）

**它比原句强在四点**：
1. **把量级摊在明面上（四分之一）**，等于在开场就把最大的雷自己拆了 —— NOTES 里作者自己的策略就是"你自己先承认，比被人在 Q&A 里挑出来强"。
2. **把"重要性之争"换成"可占有性之争"**，这一步换轴让整句变得难以反驳：没人能论证"大家用的不是同几个模型"。
3. **它自带对第一个反驳的答案**。"该不该多买模型"这个问题在句子内部就被回答了：该买，但买不到差异化。
4. **它和收尾的第 10 条形成闭环**：开场说"差异化只长在那四分之一里"，收尾说"剩下那层只有内行知道的约束只能内行自己焊" —— 同一句话的两端。

**配套的证据行也要换**：把 thesis 页副行里的「6.7% → 68.3%」降级到第二行小字，**主证据换成 Gemini 3 Pro 的 73.93 / 65.84**（官方榜、一手、反直觉、且不需要任何"最弱模型"的免责声明）。原来的 6.7→68.3 保留，但必须同行写上「最弱模型上的极值，中位数 5.39 分」。

### 一个更激进的备选（如果愿意冒险）

> **「大家用的是同几个模型 —— 所以你和别人的差距，只可能出在模型外面那一层。」**（33 字）

优点：完全不依赖任何数字，因此完全不可能被数据挑刺；且它把"造 harness"从技术选择变成竞争必然。
缺点：它放弃了这场分享最硬的一张牌（那场受控实验），**而这张牌恰恰是作者在 P3 自评为"最值钱的三个点"之首**。开场就把最好的证据藏起来，不划算。

**所以推荐第一版，不推荐备选版。**
