## 1. 本章一句话

**2022–2026 这四年真正被证伪的不是「模型不够强」，而是「模型够强就够了」——行业花了三年才把「可控性 / 可观测性 / 可复现性」这三样东西从模型内部搬到模型外面，而 harness 就是那个外面。**

配套的演讲版落点（扉页已埋钩子）：2023 年那场热潮不是被模型能力打退的，是被「没法衡量、没法收敛、没法复现」打退的；2025-09-29 是这套认知被官方公开承认的那一天。

## 2. 论点链

### 论点 1 · 第一幕赌的是 prompt，输的是收敛性，不是智力

**断言**：2022-10 → 2023-04 这半年确立的信念是「模型够强 + prompt 够好 = agent 能自主完成任务」（s05 底部原文）。它被证伪的方式不是模型答错题，而是循环停不下来、记不住、说不清。

**凭什么（一手）**
- ReAct arXiv v1 **2022-10-06**（arXiv:2210.03629，R01 §1，v1→v2 2022-11-27→v3 2023-03-10，ICLR 2023 camera ready）。「Thought → Action → Observation」交替是今天所有主循环的祖型。
- AutoGPT 首次 commit **2023-03-16T02:58:21Z**，commit message 全文只有 `Initial prompt.`，唯一文件 `prompt.txt`（commit b099adc，R01 §3.2）。这个 commit 本身就是「信念」的物证。
- 批评侧有署名有日期有实测：Tom's Hardware 主编 Avram Piltch，**2023-04-22T14:44:37+00:00**，原句 "more proofs of concept than useful utilities"、"like an Energizer Bunny, the agent will keep going and going on the wrong path"、"it may keep running and draining your OpenAPI account of credits forever"（R01 §6.2）。
- 四条归纳（R01 §6.4）：无法收敛 / 记忆失效 / 烧钱 / 不可干预。**没有一条是「模型太笨」**。

**反方或边界**
- 说「不是智力问题」有点过头：GAIA 上 GPT-4+插件只有 15%，其中显然含能力成分。诚实表述应是「能力与工程都不足，但 2023 年只有工程侧可动」。
- 「10 万 star 是热潮顶点」是 star 曲线的解读，不是因果证据。批评与 star 峰值恰好同日（04-22）是巧合级的强证据，但仍是相关不是因果。

## 3. 被低估的点

### 3.1 范式转移的第一驱动力是「尺子」，不是能力、不是成本、不是工具链

这是本章最该讲、但页面上只是暗示的一条。用时间线自己论证：

- **不是能力**。模型能力在 2023 年是**上升**的（GPT-4 2023-03-14），可 agent 的评价反而在同一年转向负面（04-22 批评潮、10-10 SWE-bench 1.96%、11-21 GAIA 15%）。能力上升而信心下降，说明瓶颈不在能力这条轴上。
- **不是成本**。成本恰恰是**反向**的。2023 年的核心批评之一就是烧钱（Tom's Guide 逐步调 GPT-4；BabyAGI README 自带 "can result in high API usage" 警告）。而到 2026 年价格大幅下降（Opus 4.5 降 66% 至 $5/$25，Sonnet 5 促销 $2/$10）之后，harness 反而变**更重**：2026-03-24 的官方对照里，同一个 Retro Game Maker 任务，单 agent 20 分钟 **$9**，完整 harness 6 小时 **$200**——**贵 20 倍以上，但 solo 那份是坏的**。人们是在明知贵 20 倍的情况下选了 harness。所以成本不是动因，是被付出的代价。
- **工具链是前提，不是原因**。Function Calling（2023-06-13）把工具调用从「正则解析模型输出」变成 API 一等公民，MCP（2024-11-25）把 N×M 变成 1×N。这两步的作用是**把工程师的注意力从底层 hack 里解放出来**——在此之前，harness 的力气全花在 output parser 上，根本没有余量去做 loop / context / 验证回路。
- **真正的拐点是可测量性**。2023 上半年几乎没有 agent benchmark，全靠 Twitter demo（R01 §7.2 明确列为「缺少评测」）。AgentBench（2023-08-07）、SWE-bench（2023-10-10）、GAIA（2023-11-21）在同一年尾部密集出现。**只有当差距被量化成一个数，「不是 prompt 不够好」这句话才能被公开说出口**；也只有当 harness 能被**单独测量**（同模型换 harness），它才可能成为一个独立的工程学科。
  - 佐证 A：Aider 的 edit format 实证调优（R03 §6）。
  - 佐证 B：Can Bölük《The Harness Problem》（2026-02-12）：180 个 React bug 修复任务 × 3 次运行 × 16 个 LLM，每次全新会话、4 个工具，唯一变量是编辑格式。
  - 佐证 C：Terminal-Bench 把 benchmark 与 harness 正式拆成两件事（Harbor，2025-11-07 与 2.0 同期）。

**一句话版本**：`让模型自己想办法 → 工程化 harness` 的转移，是**评测基础设施先于工程实践**发生的。先有尺子，harness 才从「玄学技巧」变成「可优化的自变量」。这也解释了为什么提出循环的人（姚顺雨）后来去做了尺子——他比谁都早看到瓶颈换了位置。

### 3.2 「harness 变重」和「harness 让路」是同时发生的，不是先后

页面上把 output styles 弃用当「可能的第六幕」，暗示它在 harness 变重**之后**。但时间戳不支持这个先后关系：`2.0.30` 是 **2025-10-30**，它**早于** 2025-11-04（code execution with MCP）、2025-11-24（advanced tool use）、2025-11-26（long-running harness）、2026-03-24（Planner/Generator/Evaluator）、2026-05-28（dynamic workflows）。

真实图景是：**同一时期，harness 在两个方向同时动作——在模型确实做不好的地方加重（权限、沙箱、状态持久化、验证回路、并行调度），在模型已经会做的地方主动瘦身（内建 system prompt 层的 scaffolding）**。这不是矛盾，是一条判据：**harness 该管的是模型「拿不到」的东西（外部状态、权限边界、跨窗口持久化），不是模型「不会想」的东西。**

### 3.3 「生成与评判必须结构性分离」是本章唯一的架构级结论，而它不是 prompt 技巧

2026-03-24 的 Planner / Generator / Evaluator 三 agent 架构，其理由不是「三个比一个好」，而是一条关于**偏见来源**的判断：让 LLM 生成代码再自评，它会自信地夸自己；**evaluator 从未见过生成过程，因此没有沉没成本偏见**。这是整章里唯一一条「无法靠更强的模型解决」的结论——它是结构问题，不是能力问题。这条直接支撑全场主张（模型决定上限，harness 决定兑现多少），也直接预告 CH7 的 planner/executor 分工与 Grok 只做复核。
