上一讲讲 omp 那一页，错了三处

这次是把仓库整个 clone 下来重查的。错在哪、为什么会错，都写清楚。

① FORK.md 的归属

最严重
  • 上一讲说：omp 最该抄的是它的 FORK.md tier 成本模型，页脚标了 oh-my-pi/FORK.md
  • 实情：该文件从未存在于 can1357/oh-my-pi。全史 16,613 commit，git log --all -- FORK.md 零命中
  • 那份 tier 模型出自某个私有下游 fork 自己写的维护手册，被我张冠李戴
  • tier 模型本身依然成立 —— 但它不是 omp 的东西，本讲按「某下游 fork 的做法」重新归属

② 「画成点阵图」

措辞误导
  • 上一讲说：snapcompact 把旧记录画成点阵图，零 LLM 调用
  • 实情：方向对，但不是信息可视化，是缩微胶片 —— 文本用点阵字体印成 PNG，vision 模型 OCR 读回
  • 「零 LLM 调用」也要限定：是零额外调用，帧此后每轮重附，按 vision token 计费
  • 这个区别不是抠字眼 —— 它决定了压缩率怎么算，见 CH3

③ BM25 工具发现

已过时
  • 上一讲说：默认只给 6 个必备工具，其余模型自己 BM25 搜出来
  • 实情：该机制已被删除，CHANGELOG 有明确删除记录，改为 xd:// 虚拟设备挂载
  • 写上一讲时依据的是 v16.3.12 的旧笔记；omp 2.4 天一个版本号，讲快速演进的项目，取证日期必须和结论绑在一起
  • 本讲每页页脚都标了取证基准 HEAD，就是为了防这种事
