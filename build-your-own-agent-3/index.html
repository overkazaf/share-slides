关于这一篇

一个人的 fork，凭什么值一整讲：它把每个决定的代价都写在代码里

这一讲全部结论来自本地 clone 的逐包取证，八份研究笔记同步开源。

为什么是它

  • 第一讲给了 harness 七层地图，omp 是唯一一个七层全点满的公开样本
  • 它和 pi 同一份基座，所以每一处差异都是一个可归因的工程决定，不是风格差异
  • 更难得的是它把失败也留在仓库里 —— 回滚记录、issue 编号、"这条更慢别切"的规矩

你能带走什么

按可迁移性排
  • 规则三桶路由 —— 同一份规则，按时间尺度配不同执行时机
  • 逐工具并发调度 —— 13 行，抄完就能用
  • 把口味问题变成可测问题 —— 自建 edit benchmark 的做法
  • 一份别抄清单 —— 六项明确的过度工程，附代价数字

这一讲不做什么

  • 不做产品推荐 —— 不劝你换工具，omp 的口味很重，多数人不该用
  • 不跑分 —— 性能数字只引用仓库内 benchmark，本机未装 bun，未实跑的一律标注
  • 先认错再讲课 —— 下一页是上一讲的三处更正

① FORK.md 的归属

最严重
  • 上一讲说：omp 最该抄的是它的 FORK.md tier 成本模型，页脚标了 oh-my-pi/FORK.md
  • 实情：该文件从未存在于 can1357/oh-my-pi。全史 16,613 commit，git log --all -- FORK.md 零命中

② 「画成点阵图」

措辞误导
  • 上一讲说：snapcompact 把旧记录画成点阵图，零 LLM 调用
  • 实情：方向对，但不是信息可视化，是缩微胶片 —— 文本用点阵字体印成 PNG，vision 模型 OCR 读回

Rust 热路径

一个纯 TS 的 agent，为什么要自研 9 个 Rust crate？
答案不是「Rust 更快」，是把子进程边界换成函数调用边界 —— 收益和代价，全部来自同一处边界的消失。
    本章内容
  • 234 万行 shell 里 69% 不是 shell那 2.8 万行省的是 token 和注意力，不是 CPU
  • 24一行 assert 讲清整件事同进程化之后，POSIX 白送的 fd 表 / cwd / 信号全部失效
  • 25最诚实的一张 benchmark小 payload 上 Rust 0.86×，更慢；「若更慢，不要切换调用点」
自研 Rust 实测 84,448 行（9 个 crate，vendored 的 100,565 行不算），约等于全仓 TS 的 6.7% —— 不是用 Rust 重写 agent，是把最脏的 6% 换成 Rust。
