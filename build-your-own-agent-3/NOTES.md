## 五、五个最容易被挑刺的地方

### 1️⃣ P32 第⑥条：stats 绑 `0.0.0.0` 是推断不是实测

**读码所见（`[A]`）**：`packages/stats/src/server.ts:304` 的 `Bun.serve({ port })` 未传 hostname，CORS 是 `*`。
**推断部分（`[B]`）**：「因此绑 `0.0.0.0`」依赖 Bun 的默认 hostname 行为 —— 本机无 `bun`，**没跑过**。

页面已改成「读码推断，未实跑」。上台前想讲实的，先跑：

```bash
omp stats            # 另开一个终端
lsof -nP -iTCP:3847 -sTCP:LISTEN
```

被问「你确定吗」→ 老实答：代码里确实没传 hostname，但我没实测过绑定结果。

### 2️⃣ P16 的 chars/token 表是手算的

按代码公式推算，不是实测。页面上有琥珀标注框。被追问就把公式出处报出来，别硬撑。

### 3️⃣ P17 的 f1 数字来自代码注释

`.351 → .806` 写在源码注释里，`research/` 目录只有脚本没有结果文件。**不是本次实跑。**
另外这页有两个口径：字符/帧 165,830 → 13,916 是 **11.9×**，chars/token 33.0 → 4.23 是 **7.8×**。标题说的是「一个量级」，别把两个数混着念。

### 4️⃣ P10–P13 的「pi 有 omp 无」不能说成「omp 删了」

`docs/porting-from-pi-mono.md` 记的上游同步点是 **2026-03-22**，而 pi 对比基准是 **08-01**，中间差了四个多月。个别缺失项可能是上游后加的。统一口径：**「本次对比基准下未见对应实现」**。

### 5️⃣ P31 的 benchmark 成绩是仓库内快照

未标注样本量与生成时间。R09 推测每模型 20 个 task（因为 `success_pct` 都是 5 的倍数），**这个推测没上页**，被问到可以说，但要说明是推测。

## 六、四个最抓人的点，别讲快了

1. **P8 · omp 在用 omp 开发 omp** —— 16,613 个 commit 里 2,564 个署名机器人，`CONTRIBUTING.md` 让人类别抢机器人的活。这是全场最有冲击力的一条
2. **P16 · 压缩率几乎不省** —— 听众会预期「压缩技术=省 token」，结果 Claude 上 4.2 vs 纯文本 4.0。反转在于卖点是**确定性**，不是压缩率
3. **P23 · 4 万行 shell 里 69% 不是 shell** —— 省的是 token 和注意力不是 CPU。把它当性能优化讲，整段就废了
4. **P25 · 0.86×，Rust 更慢** —— 一个把 8 万行押在 Rust 上的项目，自己把「更慢」的那行签进了仓库，还写下规矩「If native is slower, do not switch callsites.」
